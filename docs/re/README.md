# OpenMaker reverse engineering notes

Goal: document the FileMaker Pro 26 client's behavior, wire protocol, file
formats, and layout/rendering model, and FileMaker Server's hosting, well
enough to build OpenMaker, a compatible Rust client and server. First
target: Ubuntu Desktop.

## Clean-room rule

These notes describe behavior, formats, and interfaces. The OpenMaker
implementation is written from these notes, never by copying or translating
decompiled code. Evidence in these notes cites symbol names, addresses, string
offsets, and REA Evidence IDs; it does not paste or paraphrase decompiled code.

### FileMaker Pro 26.1.1

FileMaker Pro 26.1.1 (November 2026; Claris release notes, FileMaker Pro
26.1.1) is the newest client. FileMaker Server 26.1.1 has been announced
but not released, so the Linux engine reference stays at 26.0.3. The
specs record what 26.1.1 changes where each fact belongs, marked
"26.1.1"; F112-F114 below summarize them. Compared with 26.0.3 [O]:

- Windows installs the same files. The Mac app adds nibs (Go to Line, an
  agent-access prompt and manager, an Excel runtime options sheet) and
  ships its ten localized `NewLogin.strings` as nibs. The bundled starter
  solutions (`DynamicTemplates/*/*.fmp12`) and themes are
  byte-identical on macOS and Windows.
- All 11 embedded `.proto` schemas are byte-identical (protobuf-schemas.md).
- The catalogs stay at 26.0.3; catalogs/README.md lists what 26.1.1 adds
  ([#338](https://github.com/OpenMaker-Dev/openmaker/issues/338)).
- The new behavior is in the Mac binaries' symbols and strings; the
  method and the per-binary diffs are in `re/work/fm-26.1.1/`.

## Live observations

Behavior that the binaries cannot settle is observed on a lab FileMaker
Server 26.0 and FileMaker Pro 26.0.3. Access to them, their addresses and
the test files on them are documented outside this repository, in the
maintainer's lab guide; this file and the specs cite them only as "the lab
server" or a capture name.

A FileMaker Server's client port, as observed on 2026-10-27:

- 5003/tcp, TLS 1.3 (`TLS_AES_256_GCM_SHA384`), no ALPN negotiated when
  offered `h2,http/1.1`. The server sends nothing first and closes on
  malformed GIOP and HTTP probes. It requires a client certificate (F10).
- 80, 443, 2399, 3000, 5013 and 8443 are also open. 443 serves the Data
  API (`/fmi/data/vLatest/productInfo` answers unauthenticated).

FileMaker Pro sessions are recorded through `tools/capture/fm_tls_proxy.py`,
a relay that presents a certificate the client trusts, forwards to the
server with normal verification, presents a client certificate upstream
(`--upstream-cert`, see F9-F11) and writes each connection's plaintext
streams to `re/captures/<session>/`. Captures contain credentials and the
license key: they stay git-ignored, and `tools/capture/giop_dump.py` masks
the sensitive values when decoding them.

On macOS, a second FileMaker Pro process started with `CFFIXED_USER_HOME`
still shares the `com.filemaker.client.pro12` preferences domain. Export it
before a capture session (`defaults export com.filemaker.client.pro12
<file>`) and compare afterwards.

- REA 6.8.0's CLI ignores `REA_GHIDRA_PROJECT_PATH` and re-imports the binary

  use the read-only headless scripts in `tools/ghidra/` (`DecompileList.java`,
  `XrefsList.java`) against a copy of the project; about 10 seconds per batch.

  object type number stored in files; see layout-model.md.
